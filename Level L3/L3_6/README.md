# Sales Tracker

Sales Tracker - это сервис для отслеживания продаж и расчета аналитики. Сервис предоставляет REST API для управления записями о продажах (создание, чтение, обновление, удаление) и получения детализированной аналитической информации.

## Использованные библиотеки

В проекте используются следующие основные библиотеки:
- [gin-gonic/gin](https://github.com/gin-gonic/gin) - HTTP-роутер и веб-фреймворк для обработки запросов.
- [google/uuid](https://github.com/google/uuid) - Для генерации уникальных идентификаторов (UUID).
- [ilyakaznacheev/cleanenv](https://github.com/ilyakaznacheev/cleanenv) - Для удобного чтения конфигурации из переменных окружения (включая файл `.env`).
- `github.com/wb-go/wbf` - Внутренняя/кастомная библиотека, предоставляющая расширения для работы с базой данных PostgreSQL (`dbpg`), логирования (`zlog`) и HTTP-сервера (`ginext`).

## Структура проекта

Проект организован в соответствии с принципами Clean Architecture:

- `cmd/sales_tracker/` - Точка входа в приложение (`main.go`).
- `internal/` - Внутренняя логика приложения, разбитая по слоям:
  - `app/` - Инициализация сервиса, настройка маршрутов (роутинга) и запуск HTTP-сервера.
  - `config/` - Структуры конфигурации и логика их подгрузки.
  - `handler/` - Слой HTTP-обработчиков (ручки). Транслирует HTTP-запросы в вызовы бизнес-логики и форматирует ответы.
  - `usecase/` - Слой бизнес-логики.
  - `repository/` - Слой доступа к данным. Отвечает за взаимодействие с базой данных PostgreSQL.
  - `entity/` - Доменные сущности (структуры данных запросов, ответов и хранения).
  - `middleware/` - HTTP-middleware.
  - `analytics/` - Расчетов аналитики и запись в файл.
- `migrations/` - Миграции для инициализации структуры базы данных.
- `pkg/` - Модули и утилиты, которые могут быть переиспользованы (например, исходники пакета `wbf`).
- `web/` - Статические файлы для фронтенда (CSS, JS, HTML).
- `Dockerfile` и `docker-compose.yml` - Файлы для сборки образа и развертывания проекта в Docker.

## Как запустить проект

Для локального запуска вам понадобятся **Docker** и **Docker Compose**.

1. Откройте терминал в корневой папке проекта.
2. Проверьте настройки в файле `.env` (в нем уже заданы параметры по умолчанию для БД и приложения).
3. Выполните команду запуска контейнеров:
   ```bash
   docker-compose up -d --build
   ```
4. После того как контейнеры соберутся и запустятся, приложение будет доступно.
5. Фронтенд (статические файлы) можно открыть в браузере по адресу: `http://localhost:8081/`. Сам бекенд-сервис слушает порт `8081`, а база данных PostgreSQL занимает порт `5432`.

## Описание API (Ручки)

### 1. Создать запись
- **Метод**: `POST`
- **Маршрут**: `/items`
- **Тело запроса (JSON)**:
  ```json
  {
    "title": "Название товара",
    "amount": 1500.50,
    "date": "2025-11-07T14:30:00Z",
    "category": "Electronics"
  }
  ```
- **Ответ (200 OK)**:
  `{"create_id": "uuid-новой-записи"}`

### 2. Получить список записей
- **Метод**: `GET`
- **Маршрут**: `/items`
- **Query-параметры** (опционально): 
  - `from` - начальная дата (поддерживаются форматы `RFC3339`, `YYYY-MM-DD HH:MM:SS` или `YYYY-MM-DD`).
  - `to` - конечная дата.
- **Ответ (200 OK)**:
  ```json
  [
    {
      "id": "uuid-записи",
      "title": "Название товара",
      "amount": 1500.50,
      "date": "2025-11-07T14:30:00Z",
      "category": "Electronics",
      "created_at": "2025-11-07T14:30:00Z",
      "updated_at": "2025-11-07T14:30:00Z"
    }
  ]
  ```

### 3. Обновить запись
- **Метод**: `PUT`
- **Маршрут**: `/items/:id` (где `:id` - UUID обновляемой записи)
- **Тело запроса (JSON)**: Аналогично ручке создания.
- **Ответ (200 OK)**:
  `{"update_id": "uuid-обновленной-записи"}`

### 4. Удалить запись
- **Метод**: `DELETE`
- **Маршрут**: `/items/:id` (где `:id` - UUID записи)
- **Ответ (200 OK)**:
  `{"delete_id": "uuid-удаленной-записи"}`

### 5. Получить аналитику
- **Метод**: `GET`
- **Маршрут**: `/analytics`
- **Query-параметры** (опционально): 
  - `from`, `to` - временной промежуток дат для расчетов.
  - `category` - фильтрация записей по конкретной категории.
- **Ответ (200 OK)**:
  ```json
  {
    "analytics": {
      "TotalCount": 10,
      "TotalSum": 15000.0,
      "AvgAmount": 1500.0,
      "Median": 1400.0,
      "P90": 1800.0
    }
  }
  ```

### 6. Сохранить аналитику в CSV
- **Метод**: `POST`
- **Маршрут**: `/analytics/csv`
- **Query-параметры**: `from`, `to`, `category` (по аналогии с аналитикой), а также `filename` (имя файла, по желанию).
- При успешном выполнении сервер формирует и сохраняет аналитику в файл CSV.
- **Ответ (200 OK)**:
  ```json
  {
    "message": "CSV saved successfully",
    "filename": "analytics.csv"
  }
  ```
